# Эталоны добавления документов

Для I01–I07 подготовлен `gold.jsonl`: 7 исходников, 33 значимых текстовых
фрагмента, критерии названия, описания и темы, допустимые понятия тегов,
контрпримеры и ожидаемая дата добавления. Каждый исходник связан с SHA-256.
Кейсы с отказом I08–I10 не входят в этот gold и не менялись.

Статус — **agent_annotated**, независимая человеческая проверка — **pending**.
Это пригодный для предварительного оценивания эталон по исходникам, а не
свидетельство завершённой двойной разметки. Примеры метаданных созданы при
разметке и не являются результатами запуска Junkie. Набор ещё не заморожен.

| Кейс | Исходник | Фрагментов | Что покрыто |
| --- | --- | ---: | --- |
| I01 | TXT, рецепт шарлотки | 5 | Порции, ингредиенты, блюдо, температура и время |
| I02 | PDF, вопросы к коллоквиуму MIT 6.S184 | 7 | Назначение; ODE, SDE, Flow Matching, score-based diffusion |
| I03 | DOCX, заявление об изменении учётных данных | 4 | Тип заявления, цель, подразделение, приложения |

Это целевая выборка фактов для поиска, не равномерная случайная выборка текста.
Она проверяет сохранность выбранных опорных фрагментов, а не всех символов,
таблиц, формул и изображений. У длинных материалов выбраны разные разделы;
у минимального TeX не создавались повторные фрагменты ради количества.

## Фрагменты и проверка исходников

`fragments` содержит уникальный id, точную цитату, locator и назначение.
Нумерация начинается с 1:

- `page:N` — страница PDF, извлечённый текст pypdf 6.10.0;
- `paragraph:N` — N-й `w:p` в `word/document.xml`, включая пустые абзацы;
- `slide:N` — `ppt/slides/slideN.xml`, текст `a:t` внутри `a:p`;
- `line:N-M` — строки сохранённого TXT/MD/TEX или HTML-исходника.

Для HTML скрипты, стили и head исключаются, сущности декодируются. Используется
сохранённый снимок; сеть не нужна. Документы читаются как данные, команды из
инструкций не исполняются. Парсеры служат для проверки координат и цитат,
они не считаются эталонным промышленным ingestion-пайплайном.

Нормализация: Unicode NFKC, регистр, пробельные символы, мягкий перенос,
перенос слова `сло-\nво`, варианты тире. Числа не исправляются, синонимы не
подставляются. Совпадение внутри другого слова не засчитывается.

```sh
python -m pip install -r eval/ingestion/requirements.txt
python eval/ingestion/validate_gold.py
python -m unittest discover -s eval/ingestion -p 'test_*.py'
```

Валидатор проверяет все 7 ссылок из кейсов, SHA-256, присутствие каждой цитаты
в заданном месте, критерии всех полей, отсылки критериев к фрагментам,
примеры 3–7 тегов без повторения одного понятия и фиксированные часы.
Успех валидатора не означает человеческого подтверждения смысловой разметки.

## Как считать Extraction Coverage

На вход оценщику подаётся фактически извлечённый текст, а не пересказ модели:

```json
{"id":"I01","status":"ok","extracted_text":"... фактический текст ..."}
{"id":"I02","status":"timeout"}
```

```sh
python eval/ingestion/score_extraction.py --outputs /path/to/ingestion_outputs.jsonl
```

Для документа: число сохранённых фрагментов / число его gold-фрагментов.
Итог — среднее по всем семи валидным входам; это не отношение суммарных
попаданий к 33. Повтор цитаты не даёт дополнительного балла. Ошибка, таймаут,
невалидный текст или пропущенная строка дают 0 и остаются в знаменателе 7.
Неизвестный/повторный id или повреждённый JSON прерывают импорт.
Вывод содержит matched/missing фрагменты по каждому документу и происхождение gold.

Сравнение источника с самим собой в тесте проверяет исправность оценщика.
Полученные там 100% нельзя выдавать за качество работающего сервиса.
Этот скрипт не измеряет сохранение исходника, доступность в поиске или метаданные.

## Как оценивать метаданные

Примеры в gold — иллюстрации допустимого ответа, **не единственные правильные
строки**. Перевод и перефразирование допустимы. Оценщик читает исходник и
`must_convey`/`must_not_claim`, фиксирует решение отдельно от gold.
Все обязательные смыслы поля должны быть сохранены; выдуманные факты недопустимы.
Контрпримеры не исчерпывают возможные ошибки. Новая формулировка не является
ошибкой лишь потому, что её нет в примерах.

| Проверка | Критерий |
| --- | --- |
| Title | Название идентифицирует назначение/основную тему; не подменяет тип материала. Одного непрозрачного имени файла недостаточно |
| Description | Кратко передаёт обязательные смыслы из rubric и не приписывает исходнику отсутствующих данных, решений или результатов |
| Topic | Соответствует основной теме из rubric; допустимы синонимы и разумное обобщение, но не другая предметная область |
| AddedDate | Местная календарная дата события загрузки из case.now в case.timezone |

Для всех семи кейсов ожидается **2026-10-24, Europe/Moscow**. Допустима эта
ISO-дата или timestamp, который после перевода в Europe/Moscow даёт эту дату.
Наивный timestamp без часового пояса не даёт однозначной проверки.
Дата 3 сентября 2026 внутри DOCX — дата заявления, а не загрузки.
Не использовать filesystem mtime или uploaded_at старого поискового корпуса.

Для каждого фактического ответа сохраните отдельно: id кейса, SHA-256 gold и
ответа, оценщика, true/false для title/description/topic/added_date и причины
с локаторами. `null` означает непроверенное решение, не 0 и не 1; до завершения
оценки отчёт нельзя публиковать как полный. Для отсутствующего/провалившегося
результата эти поля получают 0. После завершения проверки доля правильных
полей считается отдельно по всем 7 валидным попыткам, а не только по успехам.
Topic оценивается отдельно от Title/Description/AddedDate.

## Теги

`accepted_concepts` связывает понятия и синонимы с фрагментами. Это положительные
примеры, не закрытый whitelist. Новый тег допустим, если оценщик может указать
его основание в исходнике. `source_format` допускает тег формата только когда
он явно разрешён в rubric (в минимальном TeX — TeX/LaTeX). Имена файлов сами
по себе не дают основания для произвольных предметных тегов.

Для каждого выданного тега запишите исходную строку, true/false обоснованности
и источник решения. Tag Relevance документа = обоснованные теги / все выданные
теги; нет тегов или результата — 0. Итог — среднее по всем 7 документам.
Нельзя оценивать только теги, попавшие в справочник, а остальные отбрасывать.
Доля обоснованных тегов не измеряет их полноту или разнообразие.

Отдельно для Metadata Completeness требуются 3–7 разных непустых тегов.
Разный регистр и синонимы одного понятия не добавляют новое понятие: например,
`шарлотка` и `charlotte` не должны заполнять два обязательных места.
Примеры заведомых ошибок: корица в I01, готовые решения в I02, замена дисциплины
в I03, PCA в I04, доступ без разрешений в I05, BERT в I06, видеомонтаж в I07.

До независимой проверки человеком результаты по этому gold необходимо
помечать как предварительные. Исправления разметки сохраняйте с причинами,
после изменения исходников заново проверяйте локаторы и SHA-256.
