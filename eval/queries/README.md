# Единый поисковый gold

`dev.jsonl` — полный вход оценщика для 140 поисковых кейсов. Для 30 размеченных
кейсов общие поля обязаны совпадать с `../annotation/final_gold.jsonl`.
Последний хранит решения арбитража, а не альтернативный режим оценки.
Остальные 110 кейсов этим переносом не становятся независимо размеченными.
`ingestion.jsonl` не входит в эту синхронизацию.

## Формат

`expected` содержит `action`, `relevant_doc_ids`, `clarify_candidates`, `filters`,
`order_by`, `has_more`; `id` берётся из кейса. Документы сравниваются как множества.
Дополнительные условия `all_results_required`, `forbidden_output_strings`,
`forbidden_behavior`, `clarify_attribute` сохраняются при переносе общей разметки.
`gold_steps.filters/order_by` и эти поля в `arguments_subset` поисковых вызовов
совпадают с `expected`. Лимит равен `environment.max_results`,
`search_text_contains` совпадает с `query_contains`.

Фильтры `format`, `source_type`, `doc_type` — точные существующие метаданные.
`filename` — точное имя или исходное имя без служебного префикса `NNN_`.
`uploaded_at` и `content_date` — объекты с `gte` и/или `lt`. У `content_date`
допустим `event`: дата и тип `kind` должны соответствовать одному `content_events`.
Даты загрузки не заменяют даты содержимого. Неизвестные метаданные не угадываются.

Даты имеют формат `YYYY-MM-DD`: `gte` включается, `lt` исключается; границы —
местные календарные даты timezone кейса. Хотя бы одна граница обязательна.
Отсутствие второй означает неограниченный диапазон, а не выдуманную дату.

| Запрос | Фильтр uploaded_at |
| --- | --- |
| 15 октября | `{"gte":"2026-10-15","lt":"2026-10-16"}` |
| с 15 по 18 октября включительно | `{"gte":"2026-10-15","lt":"2026-10-19"}` |
| после 17 октября | `{"gte":"2026-10-18"}` |
| по 16 октября включительно | `{"lt":"2026-10-17"}` |

Строковые даты, `uploaded_at_from/to/after` и отдельный `content_event` больше
не используются. Фильтры одинаковы в expected, шагах и вызовах.

Запросы, контекст, часы, пользователи, группы, split и статус draft сохранены.

## Проверка

Из корня репозитория, Python 3.10+, только стандартная библиотека:

```sh
python eval/annotation/scripts/validate_eval.py
python -m unittest discover -s eval/annotation/scripts -p 'test_*.py'
```

Read-only проверка отклоняет расхождения dev/final, шагов и вызовов, чужие или
неизвестные документы, невозможные фильтры, неправильный has_more, изменения
слепого входа и несогласованный арбитраж. Fixtures применяются до проверки
метаданных и доступа. Полноту смысловой релевантности валидатор не доказывает.

При изменении размеченного кейса сохраняйте основание и историю коррекции,
обновляйте final gold и арбитраж, затем expected, шаги и вызовы в dev.
При изменении действия пересматривайте обязательные вызовы и checks.
A/B не редактируйте. Изменение входа требует повторной разметки, а не подмены
blind_cases. Перед публикацией выполняйте обе команды выше.
