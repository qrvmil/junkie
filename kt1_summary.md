# Junkie — КТ1: контракт и бюджеты

## Клиент и проблема

Пользователи — студенты и специалисты, которые хранят учебные материалы, статьи, договоры, инструкции, презентации, документацию и рецепты. Файлы и ссылки со временем накапливаются в разных папках, закладках и чатах, из-за чего их трудно находить повторно: пользователь часто помнит содержание, тему, контекст или примерную дату материала, но не его название или расположение. Junkie принимает файл или ссылку и сохраняет в персональный архив, извлекает содержимое и индексирует его для дальнейшего поиска, а затем ищет материалы по запросу пользователя на естественном языке.

## Контракт

- **Вход:** URL и поддерживаемые файлы до 25 МБ на русском или английском языке; в первой версии — PDF, DOCX, PPTX, TXT, MD и TEX, без аудио, видео и произвольных расширений.
- **При добавлении:** возвращаем название, тему, 3–7 тегов, краткое описание и дату добавления.
- **При поиске:** возвращаем до пяти наиболее подходящих материалов с названием, релевантным фрагментом, датой добавления и возможностью открыть источник. Если подходящих материалов больше пяти, показываем первые пять, сообщаем о других совпадениях и предлагаем сузить запрос.
- **При неоднозначности:** при нескольких близких результатах задаём уточняющий вопрос.
- **При отсутствии результата:** прямо сообщаем об этом и предлагаем уточнить запрос; не выдумываем ответ.
- **Изоляция данных:** пользователь видит только свой архив.
- **Хранение:** архив можно хранить локально на устройстве либо в облачном хранилище. Облако позволяет синхронизироваться между устройствами; локальный режим предназначен для материалов, которые пользователь предпочтет не хранить удаленно.
- **Внешний инференс:** локальный режим хранения не гарантирует полностью локальный инференс: необходимые для обработки данные могут передаваться внешнему API модели.

## Целевые метрики

| Метрика | Цель |
|---|---:|
| Материал успешно добавлен: доля валидных файлов, появившихся в поиске | ≥ 95 % |
| `Recall@5`: нужный материал есть в первых пяти результатах | ≥ 90 % |
| `MRR@5`: среднее обратное место первого релевантного результата в топ-5 | ≥ 0,75 |
| Правильное поведение при неуверенности: ответить, уточнить или отказать | ≥ 90 % |
| Корректная ссылка на источник: ссылка открывает сохранённый материал, показанный фрагмент есть в нём | 100 % |
| Полный ответ поиска, P95 | ≤ 6 секунд |
| Обработка добавления в фоне, P95 | ≤ 45 секунд |

## Бюджеты

Пилотная нагрузка — 100 активных пользователей, предположительно по 50 добавлений и 30 поисков в месяц: 5 000 добавлений и 3 000 поисков. Расчёт API включает модель `gemini-embedding-2` и запас 15 %.

| Вариант | Модель | Цена входа / выхода за 1 млн токенов | API в месяц |
|---|---|---:|---:|
| Экономный | Gemini 2.5 Flash-Lite | $0,10 / $0,40 | $7,80 |
| Альтернатива | GPT-6 Luna | $0,10 / $0,50 | $8,06 |
| **Основной** | **Gemini 3.5 Flash-Lite** | **$0,30 / $2,50** | **$18,64** |
| Повышенное качество | Gemini 3.8 Flash | $0,75 / $3,75 до 31.12.2026 | $34,03 |

Инфраструктура пилота: сервер (1 vCPU, 2 ГБ RAM, 50 ГБ SSD) — \$12 в месяц; объектное хранилище 250 ГБ — \$5 в месяц. С API основного варианта итог — \$35,64, или \$0,36 на активного пользователя в месяц.

## Альтернатива без системы

Ручная сортировка занимает около минуты на материал, поиск — около трёх минут. При заданной нагрузке это 2 часа 20 минут на пользователя, или 233 человеко-часа на весь пилот в месяц.

## Компромисс

Главный бюджет — качество поиска. На первом этапе сравниваются Gemini 2.5 Flash-Lite, GPT-6 Luna и Gemini 3.5 Flash-Lite; основная модель выбирается по качеству на eval-сете при соблюдении бюджетов стоимости и задержки. Более сильная модель используется только для сложных запросов, если лёгкая модель не достигает целевых метрик. Самостоятельное размещение модели не рассматривается: при 8 000 операциях в месяц сервер с GPU будет большую часть времени простаивать.

20 запросов будущего eval-сета находятся в разделе 7.1 design_doc.md.
