# КТ3: запуск и результаты

Исполняемый прототип: локальный архив, поиск, открытие документа и добавление файла.
Одна команда запускает B0, B1 или Junkie и считает метрики по сохранённым ответам.
Telegram, постоянная БД и внешний файловый сервис пока не подключены.

[Архитектура, инструменты и состояние](ARCHITECTURE.md) ·
[ADR-001](ADR-001.md) · [Оставшиеся задачи команды](REMAINING.md)

Полный прогон выполнен: [результаты](RESULTS.md), [выводы](FINDINGS.md),
[исходные ответы и пересчёт без API](results/README.md).

## Запуск

Python 3.12, зависимости:

```sh
python -m pip install -r eval/ingestion/requirements.txt
python -m junkie.run --variant B1 --output-dir runs/b1 --ingestion-timeout-s 120 --scenarios
```

Для Junkie нужен `OPENROUTER_API_KEY` в окружении. Ключ не передаём в аргументах
команды и не сохраняем в Git. Модель задаём явно:

```sh
python -m junkie.run --variant Junkie --output-dir runs/junkie \
  --model google/gemini-3.5-flash-lite --budget-usd 2 --max-calls 300 \
  --ingestion-timeout-s 120 --scenarios --judge
```

`--limit 8` выбирает фиксированный проверочный набор. Без ограничения берутся
все 140 открытых запросов, 11 чистых пар для опечаток и 10 ingestion-кейсов.
`--scenarios` добавляет 7 последовательных сценариев. Закрытый holdout не читается.
`--repeat 3` повторяет прогон; лимит долларов и вызовов общий для трёх повторов.
Существующий каталог результатов не перезаписывается.

`--judge` оценивает только формулировки о дополнительных результатах и полезность
уточнения. На B0/B1 без этого флага LLM не вызывается. При добавлении судьи его
стоимость учитывается отдельно от стоимости самого бейзлайна.

Таблицу сравнения сохранённых прогонов можно собрать без вызовов модели:

```sh
python -m kt3.summarize runs/b0 runs/b1 runs/junkie --output runs/comparison.md \
  --workflow-url https://github.com/qrvmil/junkie/actions/runs/45030212224
```

## Что сохраняется

| Файл | Содержимое |
|---|---|
| `run.json` | Commit, модель, параметры, точные промпты, настройки и выбранные кейсы |
| `preparation.json` | Подготовка корпуса, доступность файлов, время индексации |
| `search.jsonl`, `clean.jsonl` | Ответы, документы, вызовы инструментов, время и расход |
| `ingestion.jsonl` | Извлечённый текст, метаданные, отказ или результат добавления |
| `scenarios.jsonl` | Все шаги диалогов, ошибки, повторы и причина остановки |
| `messages.jsonl` | Оценки LLM-судьи с хешами входа, ответа и промпта |
| `metadata-review.jsonl` | Незавершённая форма ручной проверки метаданных |
| `report.json` | Метрики, срезы, каждый кейс, задержки, расходы, хеши входных файлов |
| `api-ledger.json` | Все API-вызовы и общий учёт бюджета, включая неудачные |

Описание формул и контрактов: [оценщик](../eval/kt3/README.md),
[формат](../eval/kt3/FORMAT.md), [покрытие](../eval/kt3/COVERAGE.md).
Отсутствующая ручная оценка помечается `pending`. Она не превращается в успешный
результат и не исключается незаметно из среднего.

## Actions

Секрет репозитория называется `OPENROUTER_API_KEY`. Изменение `kt3/request.json`
в ветке `kt3/metrics` запускает workflow. В файле фиксируются модель, состав
прогона, повторы и бюджет каждого процесса. Сумма бюджетов одного запроса
ограничена $5. Повтор workflow может снова потратить этот бюджет.

Перед запуском проверяются тесты, доступ к OpenRouter и текущий тариф. Файлы
сохраняются в артефакт Actions на 14 дней; итоговые отчёты отдельно добавляем
в репозиторий. Проверка доступа не вызывает генерацию.

## Ограничения замера

- Это открытый dev-набор, на котором разрабатывались правила. Результаты не
  являются оценкой на независимой закрытой выборке.
- В исходном корпусе метаданные получены общими правилами для всех вариантов.
  LLM-генерация метаданных Junkie проверяется на ingestion-кейсах.
- H0 требует реального прохождения человеком; runner его не имитирует.
- Контрольные примеры судьи имеют авторские метки. Они проверяют очевидные
  случаи, но не заменяют независимую двойную разметку.
- Шесть PNG остаются вне текстового индекса: OCR не реализован.
- `saved://` разрешается локальным архивом с проверкой владельца и открытием
  исходного файла. Это не публичная ссылка для браузера.
- PISR проверяет изоляцию: при поиске содержимое файлов не передаётся в LLM.
- Температура равна 0, seed не задан; API не гарантирует побитовую повторяемость.
