# Что осталось команде

## До сдачи

1. Проверить метаданные семи валидных добавлений для каждого варианта.
   Формы `metadata-review.jsonl` лежат в результатах. Заполнить автора проверки,
   title/description/topic и обоснованность каждого тега; синонимам дать один
   `concept_id`. После этого повторно запустить оценщик с `--reviews`.
   Сейчас соответствующие агрегаты честно остаются `pending`.
2. Если включаем H0 в сравнение, провести поиск реальным человеком по методике
   §8.3. Заранее записать сервис, общие кейсы и исключения, затем успех и полное
   время задачи. Автоматический запуск B0/B1 не заменяет H0.
3. Подтвердить происхождение двух независимых разметок КТ2. Уже посчитанное
   согласие не подтверждает само по себе независимость работы аннотаторов.
4. Проверить PR для сдачи, назначить преподавателя и отправить ссылку в форму курса.
   Запуск Actions и опубликованная ветка сами по себе не являются сдачей.

Можно разделить параллельно: один человек проверяет метаданные, второй проводит
H0, третий проверяет разметку и воспроизводимость, четвёртый собирает сдачу.
Семантическую ручную оценку желательно перепроверить вторым человеком хотя бы
на спорных случаях.

## Следующий эксперимент

Сначала разобрать фактические провалы из полного отчёта. В проверочном запуске
обнаружились лишние результаты при поиске нескольких версий экзамена и открытие
одной версии без уточнения. Для уточнения планировщику может понадобиться
ограниченный список реально найденных кандидатов. Это отдельное изменение
архитектуры, которое нужно сравнить с текущим прогоном.

Векторный поиск проверять после разбора случаев, где корректные фильтры и слова
не находят документ. КТ4 также потребует постоянного хранилища, связанных трасс,
дашборда, повторных прогонов и первого открытия отложенной выборки.
